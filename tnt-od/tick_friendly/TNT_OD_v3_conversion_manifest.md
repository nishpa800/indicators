## tv_ta dependency note

The Pine source uses exactly one external library function:
`tv_ta.relativeVolume(30, "", true, true)` from `import TradingView/ta/7`. It is
"Relative Volume **at Time**" and is **never** re-implemented as
`volume / ta.sma(volume, N)`. Both Python ports import the canonical shim
`rti.tv_ta_shim.relative_volume(volume, 30, anchor_timeframe="D",
is_cumulative=True, bar_timestamps=...)` (verified in `rti/SHIM_PARITY.md`).
The tick-friendly Pine keeps the `import TradingView/ta/7 as tv_ta` line unchanged.

## Unsupported / guarded constructs per output

### Output 1 — Pine tick-friendly
On TradingView tick intervals `timeframe.in_seconds(timeframe.period)` returns
0/na, which would misbucket every per-TF threshold table. Guards added (logic,
all plots and all alert names otherwise unchanged):
- `u5_tfSecRaw = timeframe.in_seconds(timeframe.period)` (raw, may be 0/na).
- `isTickChart = na(u5_tfSecRaw) or u5_tfSecRaw <= 0`.
- New input `tickTfSecOverride` (MASTER group) lets the user PIN the threshold
  bucket on tick charts; when `> 0` it wins.
- `TICK_FALLBACK_SEC = 10` (tightest sub-minute bucket) used when on a tick chart
  and no override is set.
- `u5_tfSec = tickTfSecOverride > 0 ? tickTfSecOverride : (isTickChart ?
  TICK_FALLBACK_SEC : u5_tfSecRaw)`.
- `isSubMinute = isTickChart or u5_tfSec <= 60` (tick charts treated sub-minute).
- `session.isfirstbar` and `ta.change(time("D"))` day detection: **kept as-is** —
  tick bars still carry `time`, so session-first-bar and day-change logic remain
  valid. No fixed bar-duration / wall-clock math exists elsewhere in the script.

### Output 2 — Python tick-based
- Runtime grain = N-tick / tick-derived OHLCV; bar duration NOT assumed fixed.
- `tf_sec` supplied explicitly (default 10); `tf_sec <= 0` falls back to 10 inside
  the threshold resolution, mirroring the tick-friendly Pine.
- `barstate.isconfirmed` → only confirmed bars are fed, so it is always True.
- `var`/recursive series held as explicit instance state; `nz(x[1])` →
  snapshot/prev-field reads; offset -1/0 visual semantics preserved.
- UC engine is the Pine placeholder definition (replaceable with real Squarify v2
  UC source); clearly marked.

### Output 3 — Python time-based
- Reuses the tick core verbatim; ONLY difference is `tf_sec` bound to the runtime
  timeframe (60/300/900/3600/86400…) instead of a tick fallback. `tf_sec <= 0`
  rejected (use the tick module for tick charts).
