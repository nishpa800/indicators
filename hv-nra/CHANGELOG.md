# CHANGELOG — HV NRA (volume-high 50-step ladder)

## 2026-06-29 — Remove Hot Spot (HS) detection plot — `v3_noHS`

New build: `versions/HV_NRA_50step_ladder_v3_noHS_2026-06-29.pine`
(generated by `build_hv_ladder.py`).

Removed the calendar-based **Hot Spot** detection feature in full. The study is
now a pure volume-high ladder + All-Time High (HEV). Specifically dropped:

- `useHS` input ("Show Hot Spot Signals").
- The entire `// === HOT SPOT — CALENDAR-BASED SIGNALS ===` block
  (`opExWindow`, `qtrEndWindow`, `russellWindow`, `taxLossWindow`,
  `janEffectWindow`, `hfRedemptionWindow`, `isHotSpot`).
- `plot_HS` condition, its `plotshape(... "Hot Spot" ...)`, and its
  `alertcondition(... "Hot Spot" ...)`.
- The `signalStates` HotSpot slot: array resized `22 -> 21`
  (`[0..19]` = tiers, `[20]` = HEV); `array.set(signalStates, 21, isHotSpot)` removed.
- Title shortened `HV(50-1000 step50 / HEV / HS) NRA` -> `HV(50-1000 step50 / HEV) NRA`.
- Export-comment references to `isHotSpot` / `plot_HS`.

Untouched (verbatim): the 20-tier 50-step volume-high ladder, the nested
single-marker priority chain, HEV running-max, and the non-repainting
architecture (`volume[1]` + `ta.highest(...)[1]` + `offset=-1`, plot==alert 1:1).
Verified by diff against `v2`: every changed line is Hot Spot-related; no
ladder/HEV logic changed. Passes `check_no_fixed_windows.sh`.
